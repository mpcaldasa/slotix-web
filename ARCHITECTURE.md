# Frontend architecture

The standalone Angular CLI application lives beside `reservation-core`; it does not alter or compile into the Java backend. Angular and Angular CLI 22.2.2, TypeScript 6.0.3 and RxJS 7.8.2 are pinned in `package-lock.json`. The selection was checked against Angular's [official supported releases](https://angular.dev/reference/releases) and [version compatibility table](https://angular.dev/reference/versions), which list Node `^22.22.3 || ^24.15.0 || ^26.0.0`, TypeScript `>=6.0.0 <6.1.0`, and RxJS `^6.5.3 || ^7.4.0`; the project declares the compatible Node range. The app uses standalone components, lazy feature routes, strict TypeScript/templates and Angular's stable zone-based change detection. Signals hold view and session state; RxJS handles HTTP request lifetimes and composition.

Feature pages live in `src/app/features/{auth,bookings,resources,availability,policies,members,platform,operations}`. Feature API classes own endpoint paths and payloads. Components own display and local interactions. The small `core` layer contains runtime configuration, typed HTTP access, authentication/interceptors, route guards, errors and time conversion. `shared` owns the repeated editor, confirmation dialog, feedback and state labels. There is no global data store.

The checked-in `contracts/openapi.json` was read from the backend's live `/v3/api-docs` on 2026-10-09. It provides operation and DTO shapes. `npm run contract:generate` creates the schema type definitions; `contract:check` verifies that generated output is current. The feature and role matrix is [docs/FEATURE-MATRIX.md](docs/FEATURE-MATRIX.md), with backend limitations in [docs/CONTRACT-REVIEW.md](docs/CONTRACT-REVIEW.md).

## Identity and HTTP boundary

Company login uses `POST /api/users/login` with company UUID, email and password. Platform login uses `POST /api/platform/login`. The resulting JWT is kept only in memory, decoded locally to render role-aware routes, and attached as a Bearer token only when the resolved request origin/path matches the configured `/api` base. The server's current persisted role and tenant checks remain authoritative. A `401` clears the current identity; `403` displays the permission error while preserving the session for an explicit retry or navigation. No profile, role-refresh, logout, token-revocation, context-switch or refresh endpoint exists. A browser reload requires sign-in again, and logout clears local state only.

`public/config.json` sets a same-origin API path and the current backend default company timezone `America/Bogota`. It is public, mutable deployment configuration and contains no secrets. The backend currently creates companies in this timezone and exposes no metadata route for company users. Booking response timezone snapshots take precedence where present. Availability slots remain exact UTC instants for writes. Administrative instant inputs require an explicit offset. Any deployment with companies in another timezone must override runtime config until the backend exposes authorized company metadata.

Development traffic uses `proxy.conf.json` from Angular CLI to forward `/api` to `localhost:8080`. Production should serve the compiled static files from the same origin as the API proxy/reverse proxy. `deploy/nginx.conf` provides static asset caching, `/config.json` no-cache behavior and HTML fallback. If the API is placed on a separate origin, the backend must explicitly allow that origin, `Authorization`, `Idempotency-Key`, required methods and preflight requests; `reservation-core` currently has no CORS configuration.

## Resilience and state transitions

Writes wait for server confirmation. The shared editor blocks a second submit and connects errors to their fields. Booking create generates one UUID idempotency key per unchanged selected booking payload, sends it in `Idempotency-Key`, and retains it after an uncertain network failure. A conflict tells the user to refresh availability and pick again. Generic writes are never automatically retried. Resource, booking and identity operations use server outcomes to update state. Irreversible actions use app-owned native modal confirmations. Attendance transition actions appear only for staff and only for states supported by the backend. Customer cancellation and rescheduling remain server-validated because their original policy terms are not readable through this API.

## Server rendering and dependencies

Angular's production browser builder emits immutable hashed assets under `dist/slotix-web/browser`. Initial loading retrieves `config.json` before bootstrap. Lazy feature routes limit initial JavaScript. The initial bundle budget is 350 kB warning and 500 kB error; a single component stylesheet has 4 kB warning and 8 kB error. The only UI layer is authored semantic HTML and CSS; dependencies are Angular/RxJS, Angular ESLint, Vitest coverage, and Playwright/Axe for verification.
